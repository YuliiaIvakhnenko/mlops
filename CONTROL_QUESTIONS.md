# Контрольні питання до лабораторної роботи №1

## 1. Що таке MLOps і які проблеми він вирішує?

MLOps — це набір практик для організації повного життєвого циклу моделей машинного навчання: підготовки даних, тренування, версіонування, тестування, відстеження експериментів, розгортання та моніторингу.

MLOps вирішує такі проблеми:

1. відсутність відтворюваності експериментів;
2. складність версіонування великих датасетів;
3. складність контролю різних версій моделей;
4. відсутність централізованого журналу експериментів;
5. складність переходу від навчання моделі до її використання в реальній системі.

Основні компоненти MLOps-інфраструктури: Git, DVC, MLflow, ML Pipeline, середовище залежностей, система розгортання та моніторингу.

## 2. Чому Git не підходить для версіонування великих датасетів?

Git добре працює з текстовими файлами та програмним кодом, але неефективний для великих CSV, pickle, joblib або інших бінарних файлів. Якщо зберігати великі датасети безпосередньо в Git, репозиторій швидко збільшується, клонування стає повільним, а історія змін займає багато місця.

У ML-проєкті потрібно версіонувати код, конфігурації, датасети, оброблені дані, моделі, метрики та результати експериментів. Для великих файлів краще використовувати DVC.

## 3. Що зберігається в `.dvc` файлах?

У `.dvc` файлах зберігаються метадані про файл: шлях, розмір, хеш та інформація для синхронізації з DVC remote storage.

`dvc add` додає великий файл під контроль DVC, а `git add` додає до Git тільки легкий `.dvc` файл. Сам великий файл зберігається у DVC cache або remote storage.

## 4. Назвіть чотири компоненти MLflow

Основні компоненти MLflow:

1. MLflow Tracking — відстеження експериментів;
2. MLflow Projects — пакування ML-коду для відтворюваності;
3. MLflow Models — збереження моделей у стандартному форматі;
4. MLflow Model Registry — керування версіями моделей.

Run — один запуск експерименту. Experiment — група запусків. Parameter — вхідний параметр моделі. Metric — числова оцінка якості. Artifact — файл, пов’язаний із запуском, наприклад модель або графік.

## 5. Що таке scikit-learn Pipeline?

`scikit-learn Pipeline` — це послідовність кроків обробки даних і навчання моделі. Наприклад, у цій роботі Pipeline має структуру:

```text
StandardScaler -> Classifier
```

Pipeline запобігає data leakage, тому що scaler навчається тільки на тренувальних даних під час `fit`, а тестові дані лише трансформуються вже навченим scaler.

## 6. Обґрунтуйте структуру директорій проєкту

У проєкті використано структуру:

- `data/raw` — оригінальні незмінні дані;
- `data/processed` — оброблені дані;
- `data/external` — зовнішні джерела даних;
- `models` — збережені моделі;
- `src` — вихідний код;
- `tests` — тести;
- `notebooks` — експериментальні notebooks.

Таке розділення робить проєкт зрозумілим, підтримуваним і зручним для відтворення.

## 7. Команди для клонування проєкту та отримання даних

```bash
git clone <repository-url>
cd mlops_lab1_wine_quality
pip install -r requirements.txt
dvc pull
```

Якщо використовується локальний архів, потрібно розпакувати також папку `dvc-storage` і перевірити шлях у `.dvc/config`.

## 8. Як відтворити експеримент?

Колезі потрібно виконати такі команди:

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
dvc pull
python src/train.py
mlflow ui --backend-store-uri sqlite:///mlflow.db --port 5000
```

Щоб повернутися до старої версії моделі, потрібно перейти на потрібний Git commit з відповідним `.dvc` файлом і виконати:

```bash
dvc checkout
```

або:

```bash
dvc pull
```

## 9. Порівняння результатів з Pipeline та без Pipeline

Pipeline робить навчання більш безпечним і відтворюваним. Без Pipeline легко випадково виконати масштабування на всьому датасеті до поділу на train/test, що призводить до data leakage.

У цій роботі Pipeline дозволив об’єднати preprocessing і модель в один об’єкт. Найкращий результат показала модель `RandomForest_2` з параметрами `n_estimators=200` і `max_depth=10`, accuracy = 0.9375.

Вплив гіперпараметрів:

- збільшення `n_estimators` у Random Forest підвищило стабільність моделі;
- `max_depth=10` дав кращий баланс між недонавчанням і перенавчанням;
- у Gradient Boosting менший `learning_rate` не покращив результат;
- для SVC збільшення `C` змінило баланс precision/recall, але accuracy залишилась 0.9000.
